# 03. Design

| 선택 | 대안 | 근거 | 트레이드오프 |
|---|---|---|---|
| **1) 백엔드** - FastAPI | Django, Express | 타입 힌트 기반 검증(Pydantic)과 자동 API 문서를 기본 제공한다. API 7개짜리 작은 서버에 맞는 크기다. 스택이 Python 3.11 이상으로 고정되어 있다. | Django 같은 관리자 화면·인증·ORM 일체형은 없다. 필요한 것은 직접 고르고 붙여야 한다. |
| **2) 프론트** - Vanilla JS + Tailwind CDN. 백엔드가 같은 오리진에서 제공하며 `file://` 로 직접 열지 않는다. | React, Vue | `index.html` 과 `app.js` 2개 파일만 쓰는 구조라 빌드 단계가 없다. 같은 오리진이면 CORS 설정이 필요 없다. | 컴포넌트·상태 도구가 없어 화면이 커지면 `app.js` 가 길어진다. 서버를 띄워야 화면을 볼 수 있다. |
| **3) DB** - SQLite (SQLAlchemy ORM, 추후 PostgreSQL 전환 고려) | PostgreSQL 즉시 도입 | 파일 하나로 설치 없이 돌아가 실습·MVP 에 맞다. ORM 을 쓰면 DB 교체 시 코드 변경이 작다. | 동시 쓰기에 약하다. 전환 시 SQLite 전용 설정(`sqlite_autoincrement` 등)과 타입 차이를 점검해야 한다. |
| **4) CSS** - Tailwind 만 쓴다. styled-components 금지. | styled-components | 스택이 Tailwind CDN 으로 고정되어 있고, 스타일 방식이 하나라 유지보수가 쉽다. styled-components 는 React 전제라 맞지 않는다. | 마크업의 class 문자열이 길어진다. CDN 방식이라 빌드 최적화(미사용 클래스 제거)를 쓰지 못한다. |
| **5) 받아쓰기** - Gemini API (`gemini-3.1-flash-lite`). 키는 `.env` 로만 읽고 저장소에 올리지 않는다. | Whisper 자체 구동, 브라우저 음성 인식 | 서버에 모델을 올릴 필요가 없고, 받아쓰기와 세 갈래 구분을 같은 API 로 처리할 수 있다. | 외부 서비스에 의존한다(실패 시 502, 비용·속도 제한). 녹취 내용이 외부로 전송된다. |
| **6) 상태관리** - 모듈 변수 + DOM 직접 갱신 | (명시된 대안 없음) | 화면이 4종뿐이라 별도 상태 라이브러리가 필요 없고, 데이터 흐름이 눈에 보인다. | 상태와 DOM 이 어긋나기 쉽다. 갱신 함수를 한 곳으로 모으는 규칙을 지켜야 한다. |
| **7) 디자인 시스템** - Mac OS UI 톤 (둥근 모서리, 부드러운 그림자, 반투명 카드, 시스템 폰트). 화면 요소 이름은 아래 id 표를 따른다. 배치는 `docs/화면구성.pdf` 를 따른다. | Material, Ant | 대상이 개발자가 아닌 실무자라 단정하고 익숙한 톤이 맞다. 라이브러리 없이 Tailwind 클래스만으로 만들 수 있다. | 반투명 효과(`backdrop-blur`)는 구형 브라우저에서 다르게 보일 수 있다. 컴포넌트가 기성품으로 제공되지 않아 직접 만든다. |
| **8) 테마** - 라이트/다크 토글. `localStorage` 에 저장하고 초기값은 시스템 설정을 따른다. | (명시된 대안 없음) | 사용자 선택을 새로고침 후에도 유지하고, 선택이 없을 때는 OS 설정을 존중한다. | `localStorage` 는 브라우저별로 따로 저장되어 기기 간에 공유되지 않는다. 저장이 막힌 환경에서는 시스템 설정으로 동작한다. |

## 화면 요소 이름 (7번 항목)

`docs/화면구성.pdf` 5쪽 id 표를 그대로 옮긴 것이다.

| 요소 | id | 자리 |
|---|---|---|
| 검색 입력 | q · from · to | 목록 화면 상단 |
| 목록 칸 | cards | 카드 배치 구역 |
| 넣기 폼 | title · metAt · attendees | 제목 · 일시 · 참석자 |
| 파일 · 본문 | file · body | 녹취 파일과 받아쓴 본문 |
| 버튼 | btnUp · btnSave | 받아쓰기 · 정리 |
| 결과 세 칸 | result | 요약 · 결정사항 · 할 일 |
| 상세 창 | modal | 카드를 누르면 뜨는 겹침 창 |
| 제목 수정칸 | mTitle | 상세 창 안에서 제목을 고치는 칸 |
| 할일표 | todoBody | 표의 본문 행 |

- 이 식별자 이름은 한 번 정하면 바꾸지 않는다. 화면을 다시 만들 때도 같은 이름을 쓴다.
- 바꿔야 하면 사유를 이 문서에 먼저 적는다.
- 화면 배치(4종)는 `docs/화면구성.pdf` 를 따르며 이 문서에 옮겨 적지 않는다.
- 공통: 상단 고정 헤더에 제목과 탭 3개, 테마 버튼. 본문 최대 폭 `max-w-6xl` 가운데 정렬.
