## 화면

목록 · 넣기 · 상세 · 할 일, 총 4종.

- 배치와 요소 이름은 `docs/화면구성.pdf` 를 따른다.
- 요소 id 는 그 파일에 적힌 그대로 쓴다.
- 디자인: UI 는 맥OS 스타일, CSS 라이브러리는 Tailwind 로 깔끔하고 모던하게 만든다.

## 왜 이렇게 나누는가

관심사 분리(Separation of Concerns) 원칙을 문서에도 적용한다.

- "무엇을·왜"(01), "정확히 어떻게 동작하나"(02), "어떻게 구성하나"(03), "언제 무엇을 하나"(04), "어떤 규칙으로 쓰나"(05)는 바뀌는 이유와 속도가 서로 다르다.
- 한 파일에 섞으면 하나를 고칠 때 다른 내용까지 흔들리고, 문서끼리 모순이 생기기 쉽다.
- 나눠 두면 변경 지점이 한 곳으로 좁혀지고, 어긋남이 생겼을 때 문서명과 조항으로 정확히 짚어 되물을 수 있다.
- 읽는 순서는 큰 그림에서 세부로 내려가도록 잡았다.
