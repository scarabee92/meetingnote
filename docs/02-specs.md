# 02. Specs

## 1. Meeting 모델

필드 8개, 아래 순서와 타입을 그대로 따른다.

| # | 필드 | 타입 | 필수 | 설명 |
|---|---|---|---|---|
| 1 | id | INTEGER, PK, AUTOINCREMENT | O | 자동 증가 |
| 2 | title | VARCHAR(200) | O | 제목 |
| 3 | met_at | DATETIME (UTC) | O | 회의를 한 시각 |
| 4 | attendees | TEXT | | 쉼표로 구분 |
| 5 | body | TEXT | O | 받아쓴 원문 또는 붙여넣은 메모 |
| 6 | summary | TEXT | | 요약 |
| 7 | decisions | TEXT | | 결정사항 |
| 8 | todos | TEXT | | 할 일 |

- **id**: SQLite 는 PK 만 주면 지운 id 를 다시 쓴다. 테이블에 AUTOINCREMENT 가 실제로 들어가게 한다. SQLAlchemy 를 쓰면 `sqlite_autoincrement` 를 지정한다.
- **summary / decisions / todos**: 세 갈래 결과는 각각 줄바꿈으로 구분해 저장한다.
- **todos**: 한 줄에 하나씩, `내용 | 담당자 | 기한` 형식으로 저장한다.

## 2. 세 갈래 구분 기준

아래 기준을 그대로 프롬프트에 넣는다.

- **요약**: 회의 전체를 3~5줄로 쓴다. 새로운 사실을 지어내지 않는다.
- **결정사항**: 「하기로 했다 / 확정 / 승인」 처럼 합의가 끝난 것만 넣는다. 논의만 하고 정하지 않은 것은 넣지 않는다.
- **할 일**: 담당자와 기한이 드러난 것만 넣는다. 담당자가 없으면 `미정` 으로 적는다.
- 셋 중 어디에도 들어가지 않는 잡담은 버린다.

## 3. 검증과 에러 코드

| 상황 | 상태 코드 |
|---|---|
| title / met_at / body 가 없음 | 400 |
| 없는 id | 404 |
| 스펙 외 필드가 들어옴 | 422 |
| 업로드 파일이 mp3, wav 가 아님 | 415 |
| 업로드 파일이 25MB 초과 | 413 |
| POST /api/upload 의 외부 호출 실패 | 502 |

- FastAPI 기본은 422 이므로, 검증 실패를 400 으로 바꾸는 예외 핸들러(`RequestValidationError`)를 둔다. 스펙 외 필드 오류만 422 로 남긴다.
- 스펙 외 필드를 걸러내려면 Pydantic 모델에 `extra="forbid"` 를 준다. 기본값으로 두면 모르는 필드가 조용히 무시되어 201 이 나온다.
- **met_at 은 UTC 로 저장한다.** 화면의 `datetime-local` 값은 로컬 시각이므로, 보낼 때 UTC 로 바꾸고 받아서 표시할 때 로컬로 되돌린다.

## 4. REST API (7개)

모든 경로는 `/api/` 접두사를 쓴다.

| 메서드 | 경로 | 성공 | 설명 |
|---|---|---|---|
| POST | /api/notes | 201 | 저장하며 세 갈래 구분까지 수행 |
| GET | /api/notes | 200 | 목록. `q` 로 제목·참석자 검색, `from`·`to` 로 날짜 |
| GET | /api/notes/{id} | 200 | 단건 |
| PUT | /api/notes/{id} | 200 | 수정 |
| DELETE | /api/notes/{id} | 204 | 삭제 |
| GET | /api/todos | 200 | 할 일만 모아 보기 |
| POST | /api/upload | 200 | 녹취 파일을 받아 본문 텍스트로 반환 |

- 목록 응답에는 `body` 를 제외하고, 단건 응답에는 포함한다.
- `GET /api/todos` 응답 필드: `what` / `who` / `when` / `note_id` / `note_title`. 회의 날짜 오래된 순으로 정렬한다.

## 5. 검색 규칙

- `q` 는 제목과 참석자에 대한 부분 일치다. 본문은 검색하지 않는다.
- `from`, `to` 는 `YYYY-MM-DD` 형식이고 양끝을 포함한다. `to` 는 그날 23:59:59 까지다.

## 6. 할 일의 기한

- 기한은 회의에서 말한 그대로 둔다 (예: 다음 주 금요일 같은 자유 문구).
- 날짜로 바꾸지 않는다.
- 기한으로 정렬하거나 거르는 기능은 만들지 않는다.

## 7. 받아쓰기·구분 실패 처리

- 구분이 실패해도 저장은 그대로 진행하고 201 을 반환한다. 이때 `summary`, `decisions`, `todos` 는 빈 값으로 둔다.
- 화면에는 "구분 실패" 로 표시한다.
- 서버는 `logging` 으로만 남긴다.
- `POST /api/upload` 가 외부 호출에서 실패하면 502 를 반환한다.
